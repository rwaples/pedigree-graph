# v0.8 thermo-nuclear code-quality review

## Scope

This review covers the committed `v0.8` branch at `ce698ec` relative to `main` at `638b4b4`. The repository has no `master` branch.

The review focuses on structure, maintainability, abstraction quality, boundary contracts, and opportunities to remove complexity without changing intended behavior.

## Findings

### 1. Blocker: relationship semantics have two independent implementations

The Rust classifier explicitly reproduces the Python matrix classifier "bit for bit":

- `crates/core/src/relationships/engine.rs:18-31`
- `crates/core/src/relationships/engine.rs:42-76`
- `crates/core/src/relationships/engine.rs:184-263`
- `pedigree_graph/_pair_extractor.py:293-540`
- `pedigree_graph/_pair_extractor.py:671-695`

Category order and degree are duplicated in Rust at `crates/core/src/relationships/category.rs:1-104`. The native binding returns an unnamed positional array at `crates/python/src/lib.rs:294-298`, which Python assigns to codes by zipping against its separate registry at `pedigree_graph/_relationship_counts.py:73-75`. An ordering drift would silently assign valid counts to the wrong relationship codes.

#### Suggested restructuring

Use one native classifier with separate count and pair sinks. If preserving pair orientation makes that impractical, define the categories in one machine-readable specification and generate or verify both registries from it. The native boundary should return named counts rather than a positional array.

### 2. Blocker: the Rust core exposes unchecked pedigree state

`Pedigree` and `PedigreeColumns` expose all fields publicly, and `count_pairs` cannot report invalid input:

- `crates/core/src/relationships/mod.rs:24-60`
- `crates/core/src/relationships/mod.rs:68-104`

`Engine::new` immediately indexes these parallel slices and silently clamps unsupported degrees:

- `crates/core/src/relationships/engine.rs:120-138`

A Rust caller can provide mismatched lengths or invalid rows and receive a panic from otherwise safe code. The PyO3 wrapper duplicates enough validation to protect Python callers, but the host-neutral core does not enforce its own invariants.

#### Suggested restructuring

Make the raw borrowed representation private. Construct it through `TryFrom<PedigreeColumns>` or accept the validated `graph::PedigreeGraph`. Model degree as a checked type instead of applying `min(5)`, and make public counting return `Result`.

### 3. High: relationship selector parsing belongs in a shared typed boundary

Selector validation lives in `_pair_extractor.py`, despite being reused by counts and matrices:

- `pedigree_graph/_pair_extractor.py:552-570`
- `pedigree_graph/_relationship_counts.py:31-49`
- `pedigree_graph/_kinship_matrix.py:436-458`

This leaks pair-specific details into other APIs. Calling `relationship_counts()` or `relationship_kinship_matrix()` without a selector raises an error saying `relationship_pairs()` was called incorrectly. The matrix path also materializes one-shot iterables because it validates the same selector twice.

`_validate_max_degree` uses `int(max_degree)` at `pedigree_graph/_registry.py:143-154`. It silently accepts values such as `2.9`, `"3"`, and `True`.

#### Suggested restructuring

Introduce a frozen `RelationshipSelection` parsed once at the public boundary. It should carry the canonical requested codes, highest degree, and cache key. Use `operator.index` to accept integer-like values while rejecting floats, strings, and booleans. Pass the parsed selection to every engine.

### 4. High: sparse-matrix ownership is unnecessarily stateful and not exception-safe

Every graph eagerly builds separate `_Am` and `_Af` matrices:

- `pedigree_graph/_core.py:122-170`
- `pedigree_graph/_core.py:203-232`

Only `_A = _Am + _Af` consumes them at `pedigree_graph/_core.py:281-287`. The pair extractor manually precomputes `_A2` and deletes `_Am` and `_Af` through `__dict__`:

- `pedigree_graph/_pair_extractor.py:325-331`

Other paths rebuild them manually, and cleanup only occurs after successful completion:

- `pedigree_graph/_pair_extractor.py:573-579`
- `pedigree_graph/_streaming_counter.py:83-116`
- `pedigree_graph/_streaming_counter.py:210-214`

An exception, including a warning promoted to an error, can leave transient matrices resident.

#### Suggested restructuring

Build one combined `_A` lazily from the mother and father edges. Delete `_Am`, `_Af`, `_ensure_parent_csr`, and the direct `__dict__.pop` calls. Put any remaining transient matrix cleanup behind a context manager or `finally` block.

### 5. High: effective-size orchestration is a string-dispatched, untyped second implementation

`_Prerequisites` stores unrelated values in `dict[str, Any]`, several accessors lack return types, and estimator behavior is selected through a long name-based conditional:

- `pedigree_graph/_ne_estimate.py:207-275`
- `pedigree_graph/_ne_estimate.py:276-316`

This duplicates behavior and metadata guards already owned by the standalone estimator functions. Adding or modifying an estimator requires coordinated edits to the name tuple, direct-function mapping, prerequisite methods, guard sets, and `_compute`.

The Hill fallback also suppresses every `RuntimeWarning` while privately computing variance at `pedigree_graph/_ne_estimate.py:308-313`, rather than suppressing one known warning.

#### Suggested restructuring

Replace the string memo with a typed call context using `cached_property`. Define each estimator once as a strategy that accepts that context. Both the standalone API and batch orchestrator should call the same strategy. Keep estimator names and strategies in one registry rather than maintaining a second conditional implementation.

### 6. High: `NeHillResult` encodes two states as a nullable field blob

`NeHillResult` has a mode boolean followed by roughly twenty optional or defaulted fields:

- `pedigree_graph/_ne_results.py:372-449`

Its constructor does not enforce the documented relationship between `collapses_to_ne_v` and those fields. Contradictory states are valid instances.

The producer compounds this with ten parallel lists and a large manually aligned constructor:

- `pedigree_graph/_ne_hill.py:149-204`
- `pedigree_graph/_ne_hill.py:215-265`

#### Suggested restructuring

Use a discriminated internal model for collapsed and birth-year results. Preserve current public fields through properties or serialization if compatibility requires it. Accumulate one typed `HillCohort` record per cohort, then convert those records to arrays once.

### 7. High: the benchmark harness is oversized and has brittle process and output handling

`benchmarks/_harness.py` is a new 1,045-line file. It crosses the 1,000-line threshold immediately and combines schemas, fixtures, measurement, child-process management, report parsing, rendering, persistence, and command-line handling.

Two reliability problems sit inside the same file:

- `_spawn` waits for child termination before draining piped stdout and stderr at `benchmarks/_harness.py:662-691`. A noisy child can fill either pipe and block until timeout.
- `_write` overwrites the report directly at `benchmarks/_harness.py:981-992`. An interruption can destroy the last valid partial report.

#### Suggested restructuring

Split the harness into focused modules for models and schema, process execution and measurement, and report validation and rendering. Keep `_harness.py` as a thin facade.

Redirect child output to temporary files when using `wait4`. Write reports to a sibling temporary file and publish them with `os.replace`.

### 8. Medium: public immutable result mappings rely on assertions and mutable dictionaries

`RelationshipPairs` and `RelationshipCountResult` claim immutability, but both retain ordinary dictionaries. Their constructor invariants use `assert`:

- `pedigree_graph/relationships.py:93-121`
- `pedigree_graph/relationships.py:126-170`

Those checks disappear under `python -O`, and `_blocks` or `_counts` can be mutated directly.

#### Suggested restructuring

Validate with explicit exceptions and store a tuple-backed mapping or `MappingProxyType`. A small private registry-mapping base could centralize exact-key and ordering validation along with the repeated `Mapping` methods.

## Review verdict

The branch should not pass the requested code-quality bar without resolving findings 1, 2, 4, and 7. The remaining findings should be addressed before the affected APIs and internal structures become harder to change.
